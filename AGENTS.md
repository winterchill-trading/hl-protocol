# AGENTS.md (hl-protocol)

## Purpose

Hyperliquid wire types and JSON codecs for the public `/info`, `/exchange` and websocket
APIs. This library is the message vocabulary the other repositories use to talk to
Hyperliquid or to its simulator; it does no I/O and builds no binaries.

Workspace-wide rules, the repository map and the CI model are in
`../oxcaml-claude-skills/AGENTS.md`. Read that first.

## Build and test

From this repository, inside the workspace:

```sh
opam exec --switch 5.2.0+ox -- dune build --root .. @hl-protocol/all @hl-protocol/runtest
```

For parallel work give the build its own directory, relative to the workspace root:
`DUNE_BUILD_DIR=_build-hl-protocol` in front of the same command.

Standalone, with the published dependencies:

```sh
opam repo add winterchill https://github.com/winterchill-trading/opam-repository.git
opam install . --deps-only --with-test
dune build && dune test
```

Format only this repository, after the tests pass:
`dune build --root .. @hl-protocol/fmt --auto-promote`. Never run `dune fmt` at the
workspace root.

## Conventions

- Core style: `open! Core`, an `.mli` for every module, labelled arguments, ppx_jane
  derivations, expect tests and Base_quickcheck properties. The style rules are in
  `../oxcaml-claude-skills/skills/janestreet-ocaml-style/SKILL.md`.
- Field names and shapes follow the API. A changed field is a wire change: decode and
  re-encode every captured frame in `test/fixtures` before and after the edit.
- Prices, sizes and dollar amounts reuse the `exchange-core` types with their Hyperliquid
  encodings. Do not add a second fixed-point type.
- Odoc on every public value. Comment every non-obvious encoding, saying what and why.
- The coverage table in `README.md` says which endpoints are checked against mainnet.
  Keep it honest when an endpoint is added: mark it as written from the docs unless a
  captured sample backs it.
- No `Obj.magic`. The obj-magic job in CI enforces it.

## Dependencies and dependents

- Depends on `fixed-decimal` and `exchange-core`, pinned in CI in that order.
- Used by `../hl-client`, `../hl-sim`, `../hl-mm`, `../hl-leaderboard`, `../hl-copy-core`,
  `../hl-copy-engine` and `../hl-copy-api`. A type change here reaches all of them.
- Spec: `../specs/repos/hl-protocol.md`.

## CI

`.github/workflows/ci.yml` has two jobs. `build` runs the `ox-setup` action (the switch,
with `fixed-decimal` and `exchange-core` pinned from GitHub), then `dune build` and
`dune test`. `obj-magic` calls the shared reusable workflow from `infra`. Warm runs take a
few minutes because the switch is cached on the pins.

Check a run with one `gh run list --limit 1` and at most one
`gh run watch <id> --exit-status`. Never poll in a loop; the API quota is shared.

## Pitfalls

- Derived yojson code calls the converters unqualified. Only the files that derive yojson
  need `open Ppx_yojson_conv_lib.Yojson_conv.Primitives`; an unused open fails the build
  (warning 33).
- `[@yojson.option]` accepts a missing field but rejects an explicit `null`. For APIs that
  send `null`, use a default plus a drop-if.
- Records reject unknown fields unless `[@@yojson.allow_extra_fields]` is set. Put it on
  every response type decoded from a third-party API.
- Derived variants encode as `["Ctor", ...]`. A tagged-object API needs a hand-written
  codec over a derived helper record. Inline-record constructors cannot be passed as values.
- `int64` derives an `Intlit` JSON value. Emit a plain `Int` when it fits, so the tree
  matches what Yojson parses.
- `include Comparable.Make (T)` shadows `<` and `=` for `t`, which breaks later integer
  comparisons. Use `Int.( ... )` or define integer helpers before the include.
- Two newtypes over one fixed-point implementation unify unless each comes from its own
  generative functor (`Make ()`).

## Never do

- Install or upgrade opam packages that change the compiler, `core`, `base`, `async` or
  `ppx_jane` on the shared switch. Dry-run first: `opam install --switch 5.2.0+ox --dry-run <pkg>`.
- Publish, tag or release.
- Commit credentials. `.env` is gitignored; values come from the environment only.
- Print secrets or signatures from fixtures or logs.
